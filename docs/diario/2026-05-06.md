## O que aprendi

- **`gz-sim-thruster-system` com `use_angvel_cmd=true` nao le velocidade real da junta.** Ele escuta `/model/.../joint/.../cmd_vel`. Helice girando visualmente nao prova empuxo. Validacao correta: `gz topic -e -t /model/migbot/joint/Engine_helice_1/force`.
- **`ExecuteProcess` no ROS 2 launch aceita `respawn=True, respawn_delay=N`** — vital para servicos auxiliares como `micro-ros-agent`.
- **`TimerAction(period=N)` simultaneos NAO sao deterministicos.** Para dependencia explicita, prefira gap real (8-10s) entre etapas que se conversam por socket.
- **`errno: 98 EADDRINUSE` no `micro-ros-agent`** = porta 2019 ja ocupada por outro agent (manual ou residual). `pkill -f "micro_ros_agent\|MicroXRCEAgent"` resolve antes de relancar.
- **Diagnostico rapido de DDS sem rodar tudo:** `ss -ulnp | grep 2019` mostra se o agent esta listening. Sem listener => SITL solta `No ping response`.
- **Procedimento manual em 4 terminais** (Gazebo+bridges, agent, SITL, mavlink_bridge) e fallback util quando o launch unico falha.
- **AP_DDS validado nao substitui MAVLink dos atuadores.** Pode publicar em `/ap/cmd_vel` mas o caminho dos thrusters continua sendo `SERVO_OUTPUT_RAW -> mavlink_bridge -> cmd_vel`.

## Problemas encontrados

1. **`Warning: DDS: No ping response, exiting` no QGC**
   - Causa raiz: race entre `micro_ros_agent` e SITL ao subir simultaneamente em t=15s. SITL pingava DDS antes do agent completar bind UDP.
   - Fix: agent t=10s, SITL t=18s, agent com `respawn=True`.

2. **`errno: 98` no agent durante respawn loop**
   - Causa raiz: agent manual de terminal anterior ainda segurando porta 2019 quando launch tentou subir o seu proprio.
   - Fix operacional: `pkill -f micro_ros_agent` antes de relancar.

3. **Migbot nao se movia mesmo sem warning DDS (apos primeira tentativa de relancamento)**
   - Causa raiz: bridge MAVLink nao subiu por residuos de processos anteriores poluindo portas/output.
   - Fix: kill completo (`pkill -f "sim_vehicle\|ardurover\|micro_ros\|gz sim\|parameter_bridge\|mavlink_bridge"`) seguido de relancamento limpo. Confirmado `mavlink_bridge_node` no `ros2 node list` e `cmd_vel` publicando.
